# 每日维护清理任务

`MaintenanceCleanupWorker` 是当前唯一负责站点数据清理调度的后台服务。它在 `Program` 中注册为 Hosted Service，并在每个服务器实例内持续等待下一次计划时间。原先按各自扫描间隔运行的账号、会话、认证申请、LLM 审计和孤儿文件 Worker 已经移除。

`DatabaseSettingsReloadWorker` 仍然存在，但只负责每 30 秒同步数据库配置，不执行清理。`AccountRecoveryWorker` 处理账号恢复邮件队列，也不属于维护清理。

## 调度时间

所有清理项共用数据库配置组 `CleanupSchedule`：

| 字段 | 默认值 | 时区 |
| --- | --- | --- |
| `StartTime` | `03:30` | 当前服务器的本地时区 |

Worker 每天执行一次。它计算严格晚于当前时刻的下一次计划时间，所以进程在当天计划时间之后启动时，会等待到第二天，不补跑当天任务。进程在计划时间停机也不会在恢复后补跑；系统没有持久化上次成功运行时间。

`IOptionsMonitor<CleanupScheduleOptions>` 会监听调度配置。时间变化时，Worker 取消当前等待并按新值重新计算。夏令时跳过的本地时间顺延到第一个有效分钟；重复的本地时间选择第一次出现。

每个服务实例独立调度，没有分布式锁。多实例部署会在各自的服务器本地时间执行同一轮任务，因此应统一服务器时区，并接受各清理服务自身并发保护带来的重复扫描开销。

## 执行顺序

每轮按以下顺序串行执行：

1. 删除超过绝对期限或刷新空闲期限的认证会话。
2. 按配置拒绝超时待审核认证申请。
3. 按“从未申请认证、无合法角色、长期未登录”的顺序执行账号清理。
4. 删除最后修改时间超过 24 小时的上传临时文件和无数据库引用的证件文件。
5. 按配置删除超过保留期的 LLM 审计记录。

认证会话和孤儿证件文件清理始终运行。账号、认证申请和 LLM 审计规则只有在开关开启、天数有效且对应配置已经持久化时才运行。

每项清理使用独立 DI 作用域，并在自身边界内捕获和记录异常；一项失败不会阻止后续项目。宿主停止时会取消等待和剩余工作。正常轮次结束后，Worker 再等待第二天计划时间。

## 各项边界

账号清理按配置版本在候选之间复核，完整规则见[账号清理](./account-cleanup.md)。认证申请的机器决定遇到并发变化时跳过，不与管理员争夺最终决定，详见[认证申请审核与超时拒绝](./certification-review.md)。

LLM 审计清理使用 `PrescriptionGenerateRequest.RequestTime` 计算年龄，删除时间严格早于截止时间且时间有效的全部记录。它在可串行化事务内检查 `LlmAuditCleanup` 配置版本，然后使用数据库端批量删除；配置变化时本轮不删除。

孤儿证件文件清理只识别本程序命名规则下的文件。上传临时文件超过宽限期即可删除；最终文件还必须没有认证申请引用。单个文件因 I/O 或权限问题删除失败时记录警告并继续，下一日自然重试。

`OrphanCleanupService.DeleteOrphanedAiAuditRecordsAsync()` 仍提供按“所属用户不存在”删除孤儿 AI 审计记录的服务方法，但当前每日 Worker 没有调用它。账号删除流程会删除该账号已有的 LLM 审计记录；如果数据库中存在其他来源造成的孤儿记录，需要由显式调用或后续调度设计处理。

## 运行限制

- 当前没有错过计划时间后的补偿执行。
- 当前没有跨实例的单执行者协调。
- 当前没有整轮运行历史表，结果通过结构化日志记录。
- 各清理服务不设置批次上限；大量候选可能增加数据库负载、日志量和执行时长。

这些限制是当前实现边界，不应在运维文档中表述为已经具备补跑、分布式锁或批处理能力。
