# 版本管理

EzNutrition 产品发行版本使用四段数字 `A.B.C.D`，当前版本为 `2.1.1.0`。

| 段位 | 含义 | 递增条件 |
| --- | --- | --- |
| `A` | 产品代际 | 重大产品升级、迁移边界或整体兼容承诺变化 |
| `B` | 接口契约代际 | 现有客户端必须协调升级的破坏性 HTTP/SSE 契约变化 |
| `C` | 兼容功能版本 | 新功能或兼容性增强，现有调用方无需同步修改 |
| `D` | 修订版本 | Bug、安全、性能、日志和重构等不改变契约与功能范围的调整 |

递增任一段时，其右侧各段归零；一次发布涉及多类变更时采用影响最高的段位。新增接口、可选字段或其他向后兼容能力属于 `C`，删除接口、改变字段语义或增加必填请求内容属于 `B`。Bug 修复如果破坏既有调用方，也必须按实际兼容性影响升级。

产品版本集中声明在仓库根目录的 `Directory.Build.props` 中。正式发布应同时更新该值、发布说明和 Git 标签；`D` 是已发布修订号，不作为每次 CI 构建的流水号。程序集信息版本可以附带源码提交标识用于诊断，但公共 API 返回不含构建元数据的四段产品版本。

`GET /SystemInfo/PublicInfo` 无需登录，一次返回备案号和当前后端产品版本：

```json
{
  "caseNumber": "示例备案号",
  "serverVersion": "2.1.0.0"
}
```

该组合接口替代独立备案号接口。前后端按同一发行版本发布，不为旧版系统信息接口提供客户端回退。

前端页脚只展示成功取得的备案号和版本号。前后端版本的 `A.B` 不一致时，相关版本号标红并显示“可能存在兼容问题”；缺失或无法解析的版本不触发兼容性判断。

XML 档案格式、数据库迁移、参考数据集和 JWT 签名密钥都有独立生命周期，不跟随产品版本自动变化，也不能用产品版本替代各自的兼容性标识。
