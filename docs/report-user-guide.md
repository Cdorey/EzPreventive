# 报告签发与打印（试行）

当前在门诊咨询中接入 NRS 2002、MNA-SF、MUST、膳食调查和能量核算。三种量表共用报告版式，保留实际回答、已有评分及分项结果；膳食调查和能量核算各有专用表格模板，采用本次已完成的核算结果。

## 能量核算报告

在“能量评估”页完成推荐能量计算或手工核定后，可选择“打印当前评估稿”“签发报告”或“更正已签发报告”。这些入口在生成 PDF 前打开“能量报告设置”，默认勾选以下三个节段，至少选择一个：

- **总能量核算**：采用总能量、采用依据，以及已有的程序估算、计算方法、PAL、基础能量系数和中间结果。
- **宏量营养素与三餐分配**：各营养素供能比例、每日目标量和早餐、午餐、晚餐的克数。
- **交换份**：三餐宏量营养素供能的交换份，以及各食物类别的每日交换份。

页首始终标注方案采用的总能量。三餐按当前核算的 30%、40%、30% 分配；营养素克数与交换份保留核算结果的取整方式。取消配置不生成报告，确认后生成固定预览。配置窗宽 520px，预览窗宽 1000px，小屏随视口收窄。当前面板记住上次确认的节段选择。

患者资料或 PAL 变化后需要重新核算；无效供能比例、负数交换份会提示修正。审核期间若修改患者、能量或分配，确认签发会要求重新生成预览。选项控制 PDF 展示节段，完整的能量核算契约快照随正式报告保存。更正时可重新选择节段；重印使用已归档的原件。
## 权限配置

沿用账号与角色现有 Claims 管理入口，配置 `Permission=IssueReport` 和 `Permission=PrintReport`。策略名称分别为 `IssueReportPermission`、`PrintReportPermission`；Claims 的值不要填写策略名称。

- `IssueReport`：试行授权口径是由管理员核验医师资质后授予。执行时检查该 Permission 及认证姓名，预览和确认时的签发人须一致。
- `PrintReport`：允许打印当前评估稿及已签发原件，也控制应用内报告包导出。可以单独授予需要重印报告的人员。

新增权限没有默认角色分配，不根据既有处方权限、医师角色、RD 或营养师身份自动授予。医师资质核验由现有管理流程负责；客户端执行既有 policy，不增加另一套身份认证。

## 签发与打印

1. 在咨询中填写患者姓名，完成试行量表、膳食或能量核算，在对应模块选择“签发报告”。
2. 核对 PDF 中的患者、记录、结果及签发信息，选择“确认审核并签发”。预览对应固定快照，确认保存同一份 PDF。
3. 提示已保存后，有打印权限者可打开原件打印窗口，选择打印机、纸张和缩放。
4. 后续进入档案库，选择报告记录，再次打印保存的 PDF。此过程不读取当前咨询或重新生成报告。

预览创建成功后才提供确认按钮。生成或打开预览失败时，会撤销本次待签发状态；重新生成并核对 PDF 后才能确认归档。签发时间采用预览中显示的固定时间，保存时复用该 PDF。

“打印当前评估稿”输出的 PDF 每页都有“教学 / 功能评估 · 未经医师审核”水印，页脚说明为“仅供教学或功能评估使用 · 未经医师审核签发”。评估稿不生成正式报告档案；水印由评估用途决定。打印者只有打印权限时，也可以重印其他医师已签发的原件。

三种试行量表的独立速查页也提供“打印评估稿”：采用开始评估时的年龄、身高、体重及点击打印时捕获的答案；未完成时保留未回答标记。速查输出没有正式报告编号，不创建患者、咨询或报告档案，不提供签发入口。需要正式报告时，请在咨询中完成对应量表。

膳食调查中先添加食物、填写重量与餐次，再选择“计算膳食摄入”。完成核算后可打印评估稿或签发正式报告。报告包括食物与餐次、记录重量和核算可食重量、能量及营养素、DRIs 参考比较、三大宏量营养素的食材贡献排名和膳食宝塔比较。当前录入界面未采集回顾起止日期，PDF 明确显示“回顾起止日期未记录”。单日回顾与参考值的比较用于进一步问询，报告保留这一解释。

选择“修改记录”后须重新核算。预览生成后若改变记录、患者资料或重新核算，须重新生成并审核预览才能签发。已签发原件保持原样。

膳食调查的“打印当前评估稿”“签发报告”及选定更正对象后，先打开“膳食报告设置”。默认各表显示前 10 位，并包含独立的 DRIs 参考资料节；可以输入其他正整数、选择显示全部，或关闭独立参考资料节。截止位次的并列食材全部保留。点击“生成预览”后才生成 PDF，关闭设置即可取消。当前面板沿用上次确认的选项，取消修改保留上次配置。归档原件重印直接使用保存的 PDF。

关闭独立 DRIs 小节时，营养素表中的参考范围、类型及报告快照中的参考资料仍保留。本次展示选项随预览固定，确认签发保存该预览原件。

“三大宏量营养素的食材贡献排名”分别列出蛋白质、脂肪、碳水化合物三张表，展示排名、食材及贡献量。各表按本次记录中的贡献量降序排列，同一食材跨餐次合并计算；贡献量相同者并列排名，各表独立从第 1 名开始。

营养素按宏量营养素与能量、矿物质、维生素、水分组，维生素分项与供能比缩进显示在对应总项下。核算值旁用 ↑、↓ 标示已有核算判断的高低，范围内不加箭头，未采用参考时在参考栏显示“—”。参考范围和类型分列：双边界如 `55 g-150 g` / `RNI-UL`，单边界如 `≥14 mg` / `AI-`、`≤3000 μg` / `-UL`。专项参考随独立 DRIs 参考资料节展示。新生成报告使用模板版本 4。

DRIs 速查成功取得结果后，也可打印带水印的评估稿。PDF 使用该次查询捕获的条件和结果，保留 AI/RNI、AMDR 上下限、单位、来源说明和需要人工核定的问题；不构成已签发的个体营养处方。打印不会重新请求参考数据。修改查询条件会清除旧打印入口，新查询失败或没有记录时不提供输出。

只拥有签发权限时，可以审核并归档；应用不提供打印及报告包导出入口。应用权限控制自身提供的操作，不控制浏览器或操作系统的截图与外部文件使用。

打印窗口打开不代表纸张已输出。取消打印不会撤回签发；打印失败可从档案库重试。建议采用 A4、合适纸盒和一致的缩放设置，物理打印的颜色及缩放仍由设备和驱动决定。

## 保存、备份与恢复

报告在本机保存：浏览器使用当前站点的 IndexedDB；WPF 使用当前 Windows 用户的应用档案目录。报告操作不向服务端上传患者资料、PDF 或指纹。登录、既有参考数据与用户主动使用的 AI 功能仍遵循各自现有流程。

`.ezreport` 报告包包含清单、结构化档案、当前 PDF 和各版历史 PDF。档案库可以导出原包作为备份，并在另一宿主中导入。导入会核对格式、引用和各版成品指纹；重印使用当前版本的原件。仅有 XML 的档案不能替代 PDF 原件。

“打开文档”提供只读调阅；要恢复报告到本机库，请使用“导入报告包”。普通 XML 完整展示 SOAP 等咨询资料，报告包则展示当前报告引用的内容及签发历史。

清除浏览器站点数据会移除该站点的本机档案，换浏览器或设备也不会自动同步。需要保留的报告应先导出备份。应用升级、模板调整、账号姓名或显示时区变化都不会改写已保存的 PDF。

原件缺失或内容指纹不符时，应用停止原件输出；应恢复对应备份。内容指纹用于发现不一致，不是电子签章或医师身份的独立认证。

## 更正与历史版本

在当前咨询内修改同一次量表的回答后，选择“更正已签发报告”，明确选择要更正的记录，审核后“确认更正并签发”。新版沿用报告编号并增加修订号，提交成功后才替代旧版。关闭预览、保存失败或另一个窗口抢先提交，都不会让尚未提交的草稿替代旧版；发生并发冲突时需要重新读取审核。

膳食调查或能量核算修改并重新核算后，使用该模块的同名更正入口。候选报告按患者、咨询和模块记录筛选，各模块维护各自的修订历史。

更正列表逐份读取同一患者的报告。损坏、缺失或读取失败的单份报告会被跳过，页面显示数量，其余正常报告仍可选择。全部报告不可读时会显示相应提示；损坏报告需恢复备份后再操作。

档案库展示当前版本的内容，并保留历史签发记录。普通重印输出当前版本；历史 PDF 保持原样保存在报告包中，不通过普通重印入口输出。新一次咨询或移除后重新添加的量表属于新评估，不与原评估混为同一修订链。

“签发报告”建立独立报告，“更正已签发报告”建立既有报告的新版本。同一预览的确认重试复用同一版本。当前更正操作需要原咨询及对应模块仍在工作区。历史档案提供只读调阅。

导入完整保留本机既有历史的后续版本时，应用原子更新整份报告包。若导入的是更旧版本、另一个修订分支，或它改写了本机已有版本的资源事实，应用拒绝覆盖并提示冲突；不会按签发时间选胜者。相同内容的重复导入不重复建立档案。当前读写报告包版本 2，仍能读取版本 1 的单报告包。

## 当前实施边界

独立作废、历史标记副本和正式报告单独删除的业务口径待讨论，暂不提供这些入口。含报告时暂不开放整库清空。咨询总报告、SOAP、AI 正文与其他量表尚未进入此次试行。
