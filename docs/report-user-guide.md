# 量表报告签发与打印（试行）

当前在门诊咨询中接入 NRS 2002、MNA-SF、MUST。三种量表共用报告版式，保留实际回答、已有评分及分项结果，不重新计算或调用 AI。

## 权限配置

沿用账号与角色现有 Claims 管理入口，配置 `Permission=IssueReport` 和 `Permission=PrintReport`。策略名称分别为 `IssueReportPermission`、`PrintReportPermission`；Claims 的值不要填写策略名称。

- `IssueReport`：仅由管理员向已核验的医师授予。账号必须有认证姓名，预览和确认时的签发人须一致。
- `PrintReport`：允许打印当前评估稿及已签发原件，也控制应用内报告包导出。可以单独授予需要重印报告的人员。

新增权限没有默认角色分配，不根据既有处方权限、医师角色、RD 或营养师身份自动授予。医师资质核验由现有管理流程负责；客户端执行既有 policy，不增加另一套身份认证。

## 签发与打印

1. 在咨询中填写患者姓名并完成试行量表，选择“签发报告”。
2. 核对 PDF 中的患者、量表、回答、结果及签发信息，选择“确认审核并签发”。预览对应固定快照，确认保存同一份 PDF。
3. 提示已保存后，有打印权限者可打开原件打印窗口，选择打印机、纸张和缩放。
4. 后续进入档案库，选择报告记录，再次打印保存的 PDF。此过程不读取当前咨询或重新生成报告。

“打印当前评估稿”输出每页带有“仅供教学或功能评估使用 · 未经医师审核签发”的 PDF，不生成正式报告档案。即使操作者拥有签发权限，未确认签发的评估稿仍带水印。打印者只有打印权限时，也可以重印其他医师已签发的原件。

三种试行量表的独立速查页也提供“打印评估稿”：采用开始评估时的年龄、身高、体重及点击打印时捕获的答案；未完成时保留未回答标记。速查输出没有正式报告编号，不创建患者、咨询或报告档案，不提供签发入口。需要正式报告时，请在咨询中完成对应量表。

只拥有签发权限时，可以审核并归档；应用不提供打印及报告包导出入口。应用权限控制自身提供的操作，不控制浏览器或操作系统的截图与外部文件使用。

打印窗口打开不代表纸张已输出。取消打印不会撤回签发；打印失败可从档案库重试。建议采用 A4、合适纸盒和一致的缩放设置，物理打印的颜色及缩放仍由设备和驱动决定。

## 保存、备份与恢复

报告在本机保存：浏览器使用当前站点的 IndexedDB；WPF 使用当前 Windows 用户的应用档案目录。报告操作不向服务端上传患者资料、PDF 或指纹。登录、既有参考数据与用户主动使用的 AI 功能仍遵循各自现有流程。

`.ezreport` 报告包包含清单、结构化档案、当前 PDF 和各版历史 PDF。档案库可以导出原包作为备份，并在另一宿主中导入。导入会核对格式、引用和各版成品指纹；重印使用当前版本的原件。仅有 XML 的档案不能替代 PDF 原件。

清除浏览器站点数据会移除该站点的本机档案，换浏览器或设备也不会自动同步。需要保留的报告应先导出备份。应用升级、模板调整、账号姓名或显示时区变化都不会改写已保存的 PDF。

原件缺失或内容指纹不符时，应用停止原件输出；应恢复对应备份。内容指纹用于发现不一致，不是电子签章或医师身份的独立认证。

## 更正与历史版本

在当前咨询内修改同一次量表的回答后，选择“更正已签发报告”，明确选择要更正的记录，审核后“确认更正并签发”。新版沿用报告编号并增加修订号，提交成功后才替代旧版。关闭预览、保存失败或另一个窗口抢先提交，都不会让尚未提交的草稿替代旧版；发生并发冲突时需要重新读取审核。

档案库展示当前版本的内容，并保留历史签发记录。普通重印输出当前版本；历史 PDF 保持原样保存在报告包中，不通过普通重印入口输出。新一次咨询或移除后重新添加的量表属于新评估，不与原评估混为同一修订链。

“签发报告”建立独立报告，“更正已签发报告”建立既有报告的新版本。同一预览的确认重试复用同一版本。当前更正操作需要原咨询及原量表仍在工作区；本轮没有增加从只读历史档案恢复编辑工作区的功能。

导入完整保留本机既有历史的后续版本时，应用原子更新整份报告包。若导入的是更旧版本、另一个修订分支，或它改写了本机已有版本的资源事实，应用拒绝覆盖并提示冲突；不会按签发时间选胜者。相同内容的重复导入不重复建立档案。当前读写报告包版本 2，仍能读取版本 1 的单报告包。

## 当前实施边界

独立作废、历史标记副本和正式报告单独删除的业务口径待讨论，暂不提供这些入口。含报告时暂不开放整库清空。咨询总报告、SOAP、AI 正文与其他量表尚未进入此次试行。
