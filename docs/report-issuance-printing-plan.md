# 报告签发与打印实现说明

状态：量表首版试行已完成验收，已补充调阅与失败恢复修复（`881e835`）及膳食调查、能量核算与 SOAP 报告。本文维护当前源码行为，沿用原工作方案的文件路径。

操作步骤见[使用说明](./report-user-guide.md)，运行验收及历史证据见[验收审计](./report-acceptance-audit.md)。部署环境的功能以实际安装版本为准。

## 功能范围

- 门诊咨询中的 NRS 2002、MNA-SF、MUST 提供正式签发、更正、评估稿打印和原件重印，三种量表共用模板。
- 门诊膳食调查完成核算后提供同样的报告操作，专用模板展示食物、重量、餐次、营养素结果、DRIs 和膳食宝塔比较。
- 门诊能量核算完成计算或核定后提供同样的报告操作，支持选择总能量、宏量营养素与三餐分配、交换份三个节段。
- SOAP 记录至少填写一节后支持签发、更正、评估打印和原件重印；四节标题固定保留，空节正文留空。
- 三种量表的独立速查及 DRIs 速查提供带水印的评估稿，使用当次结果快照，输出范围限于评估用途。
- 报告准备、确认、存储和打印在 Blazor 及本机宿主内完成。报告路径仅访问随应用发布的资源；登录、参考查询和用户主动使用的 AI 功能保留各自网络边界。
- 签发表示应用内的人员确认和版本冻结，内容指纹用于检查原件一致性。

## 权限与入口

现有 `PolicyList` 注册 `Permission=IssueReport` 和 `Permission=PrintReport`，策略名称分别为 `IssueReportPermission`、`PrintReportPermission`。`AuthorizeView` 与 `ReportAuthorization` 使用同一 `UserSessionService` 认证状态及 `IAuthorizationService`。

| 权限 | 签发或更正 | 评估稿打印 | 原件打印及报告包导出 |
| --- | --- | --- | --- |
| 两者都没有 | 不提供 | 不提供 | 不提供 |
| 只有 PrintReport | 不提供 | 提供 | 提供 |
| 只有 IssueReport | 提供 | 不提供 | 不提供 |
| 两者都有 | 提供 | 提供 | 提供 |

两项权限由管理员通过现有账号或角色 Claims 管理入口显式配置。试行授权口径是核验医师资质后授予 IssueReport；执行时检查 Permission、稳定账号标识与认证姓名。机构名称可选，来自当前账号资料。Admin、Physician、RD、营养师身份和 Prescription 权限本身均不包含这两项授权。

咨询量表组件分别显示“签发报告”“更正已签发报告”和“打印当前评估稿”。量表未完成时禁用签发和更正按钮；业务层检查量表完成、患者姓名、签发人及宿主存储能力。处理期间禁用重复操作，错误在组件内反馈。签发成功后可打印刚保存的报告；持久化重印入口位于档案库。

膳食调查复用 `ReportPanel`，三项入口均要求至少一项食物及已完成核算。业务层核对记录身份、食物、重量口径、餐次和保存的逐项核算结果；确认时再次核对患者资料、调查实例、核算结果和记录状态。

PrintReport 控制应用提供的报告输出。通过通用档案导出入口输出报告包时，也会检查该权限及原件完整性。普通咨询 XML 导出沿用档案工作流规则。浏览器、操作系统及已导出文件的外部操作属于这些工具各自的行为。

## 预览、确认与归档

1. `ReportWorkflow.PrepareAsync` 检查对应权限；正式签发还要求宿主支持保存、读取及原子条件提交。
2. `AssessmentReportFactory` 通过 `ArchiveContractAssembler.CreateAssessmentDocument` 捕获所选量表及患者、咨询输入快照，为冻结资源分配独立版本。报告中的年龄、身高、体重来自量表实际评分时的对象快照，正文采用已有答案和评分。
3. 准备预览时固定报告编号、修订号、模板版本、签发人及报告时间，并生成实际 PDF 字节。此时报告资源处于内存中的草稿状态。
4. `ReportPanel` 创建 PDF 预览成功后设置待签发状态并提供确认按钮。生成、模块加载、预览创建或旧预览清理失败会中止本次准备；空预览地址也视为失败。用户核对可见 PDF 后确认。
5. 确认时组件复核量表仍在工作区、最后修改时间及患者姓名；工作流复核当前权限和签发人。确认复用预览 PDF，`BindSignedPdf` 将实际字节的 SHA-256 绑定到 `NutritionReport`，签发时间沿用预览中已展示的时间。
6. 通过契约校验后，将快照、报告记录、PDF 和索引原子提交；成功后提示已签发。签发范围限于本份报告。

膳食入口为 `PrepareDietaryAsync`。`DietaryReportFactory` 经 `CreateDietaryDocument` 捕获 Patient、Consultation、DietaryRecall 和采用的 DriAssessment；食物贡献采用保存的逐项核算值，参考比较捕获已有结果。`ReportDraftAssembler` 为各模块快照组装共同的报告身份与修订引用，`PreparedReport` 绑定确切 PDF。膳食模板保留回顾日期缺失说明、单日结果解释、参考类型、单位及资料版本。签发范围包含膳食与参考资料。

膳食报告准备前，`ReportPanel` 使用独立的固定宽度 Modal：配置窗为 520px，调阅选择与 PDF 预览窗为 1000px；小屏宽度沿用组件的视口约束。配置窗展示 `DietaryReportOptionsEditor`。组件编辑排名范围和独立 DRIs 小节开关，确认后传递 Application 的不可变 `DietaryReportOptions`，由 `DietaryReportDraft` 保持到渲染结束。默认前 10 位及包含参考资料；排名为空表示全部，正整数表示最高名次并保留并列。展示配置只影响成品内容，完整输入快照继续归档。后续展示选项在该配置类型及编辑组件内扩展，存储、权限与原件重印复用现有流程。

评估稿每页的斜向水印为“教学 / 功能评估 · 未经医师审核”，页脚说明为“仅供教学或功能评估使用 · 未经医师审核签发”。水印由评估用途决定。评估稿直接交给打印窗口，正式预览须先确认归档，再读取原件打印。

同一预览保存重试复用同一版本；普通重印读取已存成品。保存失败保留原有档案，预览失败后可重新准备。签发成功后取消打印仍保留签发结果；原件缺失或指纹不符时停止输出，恢复需使用对应备份。

能量入口为 `PrepareEnergyAsync`。`EnergyReportFactory` 经 `CreateEnergyDocument` 捕获 Patient、Consultation 和现有 EnergyAssessment 契约，完整保存候选计算、采用值及分配方案。Domain 记录计算/核定采用的输入状态，报告工厂检查其与当前患者资料、PAL 一致，同时核对比例和交换份有效性。`EnergyReportDraft` 保存三餐交换份与不可变的 `EnergyReportOptions`，确认前检查患者、核算实例及各项分配是否变化。

`ReportPanel.Kind` 选择量表、膳食或能量流程。能量模块通过 UI 的 `ReportActions` 插槽接入该面板；`EnergyReportOptionsEditor` 编辑三个节段，默认全选且至少一项。配置窗与预览窗继续使用独立固定宽度。`ReportWorkflow` 的模块准备方法共用授权、更正读取与 PDF 检查；各模块提供自己的工厂和渲染器。能量模板版本为 1，位于 Presentation，直接展示现有核算结果；归档、原件重印和版本历史使用共同流程。
SOAP 入口为 `PrepareSoapAsync`。`SoapReportFactory` 经 `CreateSoapDocument` 捕获 Patient、Consultation 和现有 SoapNote 契约，`SoapReportDraft` 在确认时检查记录实例、四节文本及患者资料是否变化。`MedicalInformation.ReportActions` 插槽接入 `ReportPanel` 的 SOAP 模式，填写内容后启用操作，直接进入预览。Presentation 的 `soap-report.mjs` 模板版本为 1，以纯文本呈现 S/O/A/P，保留换行并支持跨页；空节保留标题和空白正文。共用模块准备、报告包及原件打印流程处理签发和更正。

## 本机存储和交换

报告复用 `IArchiveDocumentStore`，与咨询草稿使用不同文档键。`.ezreport` 是 ZIP 容器，当前写入版本 2，兼容读取版本 1 的单报告包：

| 组成 | 内容 |
| --- | --- |
| `manifest.json` | 报告包版本及内部档案格式 |
| `archive` | 通过既有 XML codec 编码的报告、输入快照和版本历史 |
| `report.pdf` | 当前正式版本的原件 |
| `history/{version-id}.pdf` | 各历史正式版本的原件，版本 GUID 使用无连字符的 N 格式；初版没有历史条目 |

`NutritionReport` 保存确切输入引用、模板、参与人员、签发元数据和成品指纹；PDF 字节由容器保存。本机文档 ID 使用初版报告的版本 ID，更正后保持稳定。患者索引用于归组，具体咨询与评估的匹配依据解包后的契约引用。

- WASM 将摘要与完整报告包字节保存在 IndexedDB，条件比较和写入位于同一事务。
- WPF 在受管理目录保存内容指纹命名的正文及 `.catalog` 索引；目录写锁串行化写入，以索引原子替换为提交点，失败时保留旧正文。旧版 GUID 文件名仍可读。
- 首次签发要求文档键不存在；更正以审核时读到的旧包字节作为条件。两个窗口竞争时，过期预览会收到冲突提示。
- 解包校验格式、引用闭包、修订链、每份 PDF 指纹、允许的文件名与大小，包及解压内容上限为 16 MiB，最多 1024 条 ZIP 条目。
- 导出保留原包。“导入报告包”校验后写入本机库；“打开文档”提供只读调阅。导入接受重复原包或完整保留本机历史的后续版本，拒绝回退、分叉和改写历史事实。

XML 文档用于结构化档案调阅，原样重印需要报告包中的 PDF。浏览器清除站点数据时会一并删除本机报告；跨设备迁移通过导出和导入完成。备份说明见[使用说明](./report-user-guide.md#保存备份与恢复)及[WPF 宿主](./wpf-hybrid-host.md)。

## 调阅、更正和历史

普通 XML 按完整档案投影，包含报告资源时仍显示 SOAP 等其他资料。通过 `ReportPackage` 校验的报告包向调阅器传递当前报告范围，展示其确切输入及历史签发记录。报告引用多个患者版本时，调阅采用咨询的明确对象快照。

档案库分别统计咨询和报告。复诊历史及“新建后续咨询”使用普通咨询文档；新建后续咨询从最近的咨询文档预填对象资料，建立新的工作区。

更正需要同一患者、同一次咨询和同一个量表运行实例仍在当前工作区。`ListRevisableAsync` 逐份读取同一患者的报告，筛选咨询及评估标识；损坏、缺失或 I/O 读取失败的单份报告被跳过，并返回 `UnreadableCount` 供页面提示，正常报告仍可选择。全部候选不可读时明确说明跳过原因。取消、权限拒绝和整个目录查询故障传播为失败；直接更正或打印损坏报告也会被拒绝。

`ListDietaryRevisableAsync` 复用逐份读取与故障隔离流程，按本次咨询的膳食资源身份及类型筛选。量表与膳食报告分别更正，旧包条件提交和历史保留使用同一流程。

更正草稿的 `BasedOn` 指向旧版；确认后状态为 `Amended`，`Supersedes` 从新版指向确切旧版。逻辑报告 ID 保持稳定，修订号递增，成功提交后替代关系生效。不同量表、新评估或新咨询分别建立报告。

初版使用 `ConsultationDocument`；修订历史使用 `TransferPackage` 保存多个确切快照，各快照遵循原有引用闭包。历史 PDF 保持原字节，普通重印读取当前原件。“当前”指本机已知的最新版本。

## 代码和依赖归属

| 位置 | 当前职责 |
| --- | --- |
| `Shared/Policies` | 两项 Permission 与既有策略注册 |
| `Domain`、`Assessments.Common` | 量表公共模型、具体题目、正式题序、计分和解释 |
| `Application/Reports` | 快照、签发条件、工作流、报告包及量表/膳食渲染、授权和打印端口；复用档案存储端口 |
| `Archives.Contracts`、`Archives.Xml` | 资源语义、版本、校验与 XML 编码 |
| `UI` | 通用量表及档案调阅组件，档案库报告操作回调与清单 |
| `Presentation/Reports`、`wwwroot/reports` | `ReportPanel`、权限适配、PDF 展示模型、量表/膳食/能量/SOAP/DRIs 模板、pdfmake 与静态字体 |
| `Client`、`WPF` | 平台存储、文件交换及打印窗口 |
| `Server` | 现有账号及权限管理 |

当前 PDF 引擎为随应用发布的 pdfmake 0.3.11，中文字体为 Noto Sans CJK SC，依赖许可文件随资源保存。`tools/reports/fetch_assets.py` 固定下载版本和完整性校验，供开发时重建资源。量表模板版本为 3；定义版本、模板版本、报告修订号和容器版本分别记录。

量表、膳食、能量、SOAP 与 DRIs 共用引擎、字体、表格及水印，正文模板分别维护。膳食模板版本为 4：`DietaryReportNutrients` 在 Presentation 组织营养素分组、分项缩进、参考范围与类型；箭头采用已有核算判断。三大宏量营养素的食材贡献排名分为蛋白质、脂肪、碳水化合物三表，各表独立编号，贡献量相同者并列。浏览器通过 PDF 查看器交互，WPF 使用独立 WebView2 窗口接收内存 PDF 并打开打印对话框。PDF 已嵌入字体，每次重印复用成品；纸张、缩放和色差取决于打印机设置。

JS 模块句柄在每次生成操作内释放；预览 Blob 主动关闭时释放，组件移除时由 JS 观察器回收。组件 `Dispose` 负责取消任务。实际桌面生成、控件释放和进程退出已通过验收，详见[验收审计](./report-acceptance-audit.md)。
