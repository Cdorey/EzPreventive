# 认证申请审核与超时拒绝

`CertificationReviewService` 负责审核信息保存和证件图片清理，调用方负责授权。`CertificationRequestCleanupService` 提供超时筛选、预览和执行结果，`CertificationRequestCleanupWorker` 按数据库配置调度扫描。

## 状态和并发

申请增加 `Guid Version`，EF 配置为并发字段。每次保存生成新版本，SQL 更新同时匹配主键和读取时的版本，避免在查询与保存之间覆盖其他写入。所有新增的申请修改入口都经过审核服务；未来直接修改实体或使用批量 SQL 时也必须维护版本。

人工审批允许将申请设置为 `Approved` 或 `Rejected`，包括覆盖已经完成的审核结果；不区分原结果由机器还是其他管理员产生。目标为 `Pending` 时只允许修改仍为待审核、且版本未变化的申请意见和备注，不允许重新打开已结束的申请。`RequestTime`、申请人、身份类型、机构和待审核图片引用由服务端保留；HTTP 中传入的这些字段不会覆盖数据库值。人工重新审批会覆盖处理时间和意见，更新版本，但不会恢复已经删除的图片或新增审核历史。待审核备注更新将 `ProcessedTime` 设为空。

人工通过和拒绝决定遇到并发变化时静默重读并重试，最多尝试三次保存，仍使用本次提交的意见和备注。旧页面版本与数据库不同也可基于最新版本保存。因此版本机制阻止的是未复核的覆盖，不承诺任何旧页面提交都返回冲突；人工之间按最后一次成功保存的决定生效。仅编辑意见和备注时严格检查原版本，不自动覆盖其他编辑。

扫地娘只处理仍为 `Pending`、版本与初筛一致且提交时间仍超时的申请。初筛后版本变化或保存发生并发冲突，直接静默跳过，不重试；清单保留 `Skipped`，不作为错误报警。管理员先批准时，扫地娘跳过；扫地娘先拒绝时，管理员可在自动重试中覆盖为批准。这种人工优先由业务规则实现，不依赖数据库锁的优先级。

每次人工重试使用独立 DbContext，申请被删除则返回不存在，持续竞争三次仍无法保存则报告冲突。普通存储异常不自动重试，避免把未知提交结果当作并发失败。

## HTTP 和角色

现有 `Admin/UpdateRequest` 仍接受 `ProfessionalCertificationRequestDto`，增加必传的非空 `Version`。旧客户端缺少版本时返回 400，需要刷新或更新客户端，不允许绕过版本要求。成功返回 200 和 `{ message, version }`；无效状态或版本返回 400，申请不存在返回 404，备注编辑的状态或版本不符、人工审批持续冲突时返回 409 和 `certification_changed` 错误码。人工重试成功时直接返回 200，不暴露已解决的中间冲突。

管理员页面在 409、404 后结束当前编辑并刷新清单，保留服务器最终结果，不在本地把已经处理的申请改回待审核。

前端批准时仍先调用 `UpdateUser` 授予角色和声明，再调用 `UpdateRequest`。两次请求不共享事务，后续审核冲突不会撤回已经授予的权限；这是明确接受的业务边界。自动拒绝也不授予或撤销角色。

## 预览与执行

```csharp
Task<CertificationRequestCleanupResult> RejectExpiredAsync(
    DateTimeOffset cutoffUtc,
    bool dryRun = true,
    CancellationToken cancellationToken = default);
```

筛选条件是 `Status == Pending && RequestTime < cutoffUtc`；未知提交时间（最小时间值）排除，刚好处于截止时间的申请保留。截止时间固定为本轮参数并归一化为 UTC，不能使用未来时间或最小值。年龄从用户提交申请起算，`ProcessedTime` 和管理员备注不延长期限。

默认仅预览。初筛只投影申请主键、用户主键、提交时间和版本，返回完整列表，不设批次上限。实际执行逐条复核并更新，设置统一超时拒绝意见，保留申请记录和最新备注。重复扫描不会再次处理已结束的申请。

结果条目为 `WouldReject`、`Rejected`、`Skipped` 或 `Failed`，附有原因和文件清理警告。初筛期间取消抛出取消异常；执行期间在申请之间响应取消，当前申请完成单次保存尝试及成功后的图片清理后停止，返回完整初筛清单及 `IsCanceled`。单条存储错误记录为失败后继续下一条。结果表示本轮执行时的处理情况，已拒绝的记录之后仍可能被管理员重新批准。

不设上限意味着候选和结果的内存开销与数量成正比，执行耗时随申请数量和数据库往返增加。各申请独立保存，不为整轮持有事务。

## 配置和调度

数据库配置组 `CertificationRequestCleanup` 使用 `AutoRejectEnabled`、`PendingTimeoutDays`、`SweepIntervalHours`。默认关闭，未配置扫描间隔也不运行；示例或测试天数不是产品默认值。

后台启动后检查一次，此后每分钟直接读取数据库中的有效配置，判断距离本实例上次扫描开始是否已达到配置间隔。缩短间隔在下一次检查时生效；观察到关闭开关后清空本地扫描时间，重新启用时可立即扫描。配置无效或读取失败时不使用旧 Options 缓存继续处理。手工服务入口由调用方显式传参，不受自动扫描开关限制。

自动扫描在每条申请开始前复核数据库配置版本，版本变化时停止本轮并返回 `ConfigurationChanged`，下一轮重新计算截止时间。已开始的一条申请允许完成单次保存尝试和图片清理；关闭开关不会撤销已经提交的拒绝。配置复核读取失败会中断本轮并记录异常。配置修改接口和手工清理 HTTP 接口尚未添加。

每个服务实例独立计时，重启不持久化扫描时间，也没有分布式调度锁；同时扫描时通过申请版本和待审核状态限制避免重复拒绝同一申请。该设计可能产生重复查询，扫描实例之间不设优先级，人工决定可覆盖机器结果。

## 文件与迁移

数据库保存成功后才删除所引用的图片文件；图片删除失败仍返回审核成功和清理警告，遗留文件交给已有孤儿文件清理补偿。服务创建独立 DbContext，不提交调用方无关变更，也不加入外部 `TransactionScope`。图片上传与删除之间的跨文件系统协调不属于此版本机制。

迁移 `20260903134220_AddCertificationReviewVersion` 为历史申请逐条生成非空版本，并增加 `(Status, RequestTime)` 索引。它不修改已有状态、时间或角色，不执行超时拒绝。部署应先应用迁移，再更新服务器及客户端。

测试使用隔离 SQLite 和临时目录，覆盖截止时间、完整预览、真正保存时的竞争写入、人工有限重试、机器冲突跳过、人工优先的两种提交顺序、运行时配置、取消、文件失败及 HTTP 响应；不连接实际站点数据库。SQL Server 迁移需按既有部署流程审阅和应用。
