# 认证申请审核与超时拒绝

`CertificationReviewService` 统一保存人工或自动审核决定，并在保存成功后清理证件图片。`CertificationRequestCleanupService` 提供超时筛选、预览和执行能力；生产中的自动执行由 `MaintenanceCleanupWorker` 在每日维护轮次中调用。

## 状态和并发

认证申请包含 `Guid Version` 并由 EF Core 配置为并发字段。每次保存生成新版本，SQL 更新同时匹配主键和读取时的版本，避免查询之后发生的修改被无条件覆盖。直接修改实体或使用批量 SQL 的新入口也必须维护该版本。

人工审核可以把申请保存为 `Approved` 或 `Rejected`，也可以覆盖已经完成的审核结果。人工重新审核会更新处理时间、意见和版本，但不会恢复已经删除的证件图片，也不会创建审核历史。目标为 `Pending` 时只允许修改仍然待审核且版本未变化的意见和备注；该操作不能重新打开已结束的申请，并会把 `ProcessedTime` 设为空。

人工批准或拒绝遇到并发变化时，会使用最新数据和本次提交的决定静默重试，最多三次。申请被删除时返回不存在；连续竞争三次仍无法保存时返回冲突。仅编辑待审核意见和备注时严格检查调用方版本，不自动覆盖并发编辑。

自动超时拒绝不重试冲突。它只处理初筛时为 `Pending`、执行时仍为 `Pending`、版本未变化且提交时间仍然超时的申请。管理员先完成审核时，自动任务跳过；自动任务先拒绝时，管理员随后仍可通过人工重试覆盖为批准。人工操作因此优先于机器决定。

## HTTP 和角色

现有 `Admin/UpdateRequest` 接受带非空 `Version` 的 `ProfessionalCertificationRequestDto`。缺少版本、状态无效或版本格式无效时返回 400；申请不存在返回 404；待审核备注冲突或人工审核持续冲突时返回 409，并使用 `certification_changed` 错误码。人工重试成功时直接返回 200 和新的版本。

管理员页面在 404 或 409 后刷新清单，以服务器状态为准。

批准流程仍先调用 `UpdateUser` 授予角色和声明，再调用 `UpdateRequest` 保存审核结果。两个 HTTP 请求不共享事务；后续审核冲突不会撤回已经授予的权限，这是当前接受的一致性边界。自动拒绝不会授予或撤销角色。

## 超时筛选和执行

```csharp
Task<CertificationRequestCleanupResult> RejectExpiredAsync(
    DateTimeOffset cutoffUtc,
    bool dryRun = true,
    CancellationToken cancellationToken = default);
```

候选条件为 `Status == Pending && RequestTime < cutoffUtc`。未知提交时间排除，刚好位于截止时间的申请保留。年龄从用户提交申请的 `RequestTime` 起算；`ProcessedTime` 和管理员备注不会延长期限。

默认只预览。初筛返回完整清单，不设批次上限；执行时逐条复核并写入统一的超时拒绝意见。结果状态为 `WouldReject`、`Rejected`、`Skipped` 或 `Failed`，并包含原因和证件图片清理警告。重复执行不会再次处理已经结束的申请。

初筛期间取消会抛出取消异常。执行期间在申请之间响应取消，当前申请会先完成单次保存尝试及成功后的图片清理。单条存储失败记为 `Failed`，然后继续下一条。

目前没有供管理员手工预览或执行超时拒绝的 HTTP 接口；公开服务入口可供受信任的服务端调用和测试。管理员可以通过维护配置接口控制自动执行。

## 配置和每日调度

配置组 `CertificationRequestCleanup` 包含：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `AutoRejectEnabled` | `false` | 是否启用自动超时拒绝 |
| `PendingTimeoutDays` | `null` | 从提交时间起算的超时天数 |

启用时必须提供正整数天数。调度时间不属于该配置组，全部清理任务共用 `CleanupSchedule.StartTime`，默认服务器本地时间 `03:30`。

每日任务开始该项清理时会从数据库读取最新配置。自动开关关闭、天数为空或配置尚未持久化时跳过。开始后在每条申请之间复核配置版本；任何配置保存都会使版本变化，本轮停止并报告 `ConfigurationChanged`。已经开始处理的一条申请会完成当前保存尝试和图片清理。

多实例没有分布式调度锁，各实例都会在自己的服务器本地计划时间运行。申请状态和版本检查可以避免同一申请被重复拒绝，但可能产生重复查询。

## 文件和迁移

审核数据库保存成功后才删除申请引用的证件图片。图片删除失败不会回滚审核结果，只返回清理警告；超过 24 小时宽限期的无引用文件由每日孤儿文件清理补偿。

迁移 `20260903134220_AddCertificationReviewVersion` 为历史申请生成非空版本并增加 `(Status, RequestTime)` 索引，不改变已有状态、时间或角色。部署需要先应用迁移，再更新服务器和客户端。

测试使用隔离 SQLite 和临时目录，覆盖截止时间、完整预览、并发写入、人工有限重试、机器冲突跳过、人工优先的两种顺序、取消、文件失败及 HTTP 响应，不连接实际站点数据库。SQL Server 迁移仍需按目标环境审阅和应用。
