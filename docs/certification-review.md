# 认证申请审核

`CertificationReviewService.UpdateAsync` 负责校验审核状态、查找申请、保存审核信息和清理证件图片。调用方传入申请主键、目标状态、处理意见、备注和待审核图片引用；服务返回业务结果，不依赖控制器或 HTTP 响应类型。

`AdminController.UpdateRequest` 保留管理员授权、请求模型检查和响应映射：更新成功返回原有 200 响应，申请不存在返回 404，未定义的审核状态返回 400，存储异常由控制器记录并返回 500。现有 HTTP DTO 和前端调用方式不变。

## 保留的业务行为

- 本次只提取已有更新逻辑，仍允许设置任一已定义状态，没有增加状态迁移限制。
- 每次更新均设置 `ProcessedTime`，包括目标状态为 `Pending` 的更新；`RequestTime`、申请人、身份类型和机构不变。
- `Pending` 时保存传入的图片引用；通过或拒绝时清空引用，并在数据库保存成功后尝试删除原图片。
- 文件删除失败不撤销已保存的审核结果。服务记录日志并返回 `CertificateFileCleanupFailed = true`，遗留文件可通过孤儿文件清理补偿。HTTP 仍返回成功。
- 用户角色和声明由现有账号管理流程维护。前端批准时先调用 `UpdateUser`，再调用 `UpdateRequest`；这两次请求仍不是一个原子操作。

## 后续复用边界

服务使用 scoped DbContext，应为每次独立后台操作创建作用域，避免保存无关变更，也不要套用尚未提交的外部事务后提前删除文件。

超时拒绝尚未接入。后续筛选按 `Status == Pending && RequestTime < cutoffUtc` 判断，截止时间基于用户提交申请的时间，备注修改和 `ProcessedTime` 不延长期限。执行前还需要在并发保护下复核条件；本次提取没有增加版本字段或解决手工审批与后台拒绝的并发覆盖问题。
